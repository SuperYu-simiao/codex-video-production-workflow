## 2. 用户反馈形成的版本演进

### 第一轮：确定语义触发

用户指定：

1. 小标题使用 `aurora-bloom-bg-flip`。
2. Skill/工具名使用 `assemble-then-type-flyin`，右框放 landing page、GitHub 首页或官方 Logo。
3. “一共六步”使用 `autolayout-gap-dial`。
4. “它到底是怎么做出来的？”说完后暂停真人视频，插入 `card-flock-tumble` 和一段 BGM。
5. 开头前几秒加入 `graze-face-tour`、透明 `gradient-word-sweep`、置于人物与背景之间的透明 `neon-triple-marquee`；跑马文字为“人物、字幕、信息、画面和这些动效”。

### 第二轮：加快开头并增加纵深

用户看过第一版后要求：先暂停渲染；最初画面飞入太慢，要更绚烂、更快，约 1 秒切一个效果；再加入 `flying-words` 和 `steep-tilt-glide`，两者都要透明并放在人物背后。

第五期 25fps 已确认时间编排：

| 源组件段 | 帧 | 约时长 | 作用 |
|---|---:|---:|---|
| `graze-face-tour` | `0–24` | 1.00s | 快速巡礼开场 |
| `flying-words` | `25–49` | 1.00s | 透明关键词纵深 |
| `steep-tilt-glide` | `50–74` | 1.00s | 人物背后的斜向 UI 景深 |
| `graze-face-tour` reprise | `75–99` | 1.00s | 快速回扣 |
| `gradient-word-sweep` | `96–159` | 2.56s | 透明关键词扫过 |
| `neon-triple-marquee` | `160–243` | 3.36s | 背景跑马文字 |
| `assemble-then-type-flyin` | `236–383` | 5.92s | 工具身份与真实证据框 |

这些是第五期在 25fps 下的验收参数，不是跨项目固定帧号。不同 fps 和口播长度必须按秒数与真实语义重新换算；保留的是“前 4 秒快速换运动语言，随后进入可读工具证据”的节奏弧。

### 第三轮：修正双框突兀

用户指出工具区两个方框“出现得有点突兀”。最终修改规则：

- 背景大字先退场，再进入工具信息框，避免三层同时争夺注意力。
- 左侧身份框按“描边/骨架 → 标题 → 补充文字”逐层组装。
- 右侧真实截图框比左框延迟约 `0.3s`，使用轻位移、轻缩放、短景深模糊后落定。
- 两框错峰，不同时硬弹；弱化边界和面积，人物脸保持干净。
- 右框落定进入阅读态后停止运镜。

用户随后选择 1080p v2，并明确“还是这条效果更好一点”。该版本是后续修改的开头基准，不应回到第一版的慢飞入或双框硬弹。

### 第四轮：画质与交付节奏

第一版曾用 `1280×720 / 0.85 Mb/s` 代理，再由 Remotion 二次编码，用户立即发现“不清晰”。以后：

- 视觉审美/清晰度小样直接读取原始高清素材，并以用户评审分辨率输出。
- 低清代理只用于内部时间线或解码排错，不能作为人物清晰度、抠像边缘、字幕和最终观感的评审样片。
- 小样范围已经明确时，应优先快速交付可播放文件；技术检查不能让用户等待数小时后仍看不到视频。

### 第五轮：桥接层必须真的出现

全片合成后，用户发现 20 秒附近只有 BGM、没有 `card-flock-tumble`。以后不能只验证“音频存在”或“组件单独可渲染”，必须检查最终合成层级和代表帧。

## 3. 暂停桥接的时间线不变量

第五期 25fps 基线：

```ts
export const INSERT_AT_SOURCE_FRAME = 481;
export const INSERT_DURATION_FRAMES = 113;

export const sourceFrameToMaster = (sourceFrame: number) =>
  sourceFrame < INSERT_AT_SOURCE_FRAME
    ? sourceFrame
    : sourceFrame + INSERT_DURATION_FRAMES;
```

合成顺序：

1. 母版 `0–480f` 播放源视频 `0–480f`。
2. 母版 `481–593f` 使用源片定格帧作为承接，独立播放 `card-flock-tumble`、BGM 和 SFX。
3. 母版 `594f` 起，源视频从 `481f` 继续，而不是从已经推进 113 帧的位置继续。
4. 插入点后的字幕、步骤、素材和特效统一通过 `sourceFrameToMaster()` 补偿。

“给持续播放的源视频静音，再盖一张定格图”不是暂停：它会让恢复点跳过一段口播。

桥接层必须是绝对定位覆盖层，并在最终 `OpeningPreview`/全片合成中检查，而不只检查 `CardFlockBridge` 单独 composition。第五期修复时的代表检查点是约 `19.2s / 20.0s / 21.6s / 23.0s / 23.76s`，分别覆盖起飞、飞入、叠放、烟环和恢复真人。

## 4. 图层与内容不变量

人物背后透明动效的正确层级：

```text
风格库2暗网格/原环境背景
  -> neon / flying words / steep-tilt 等透明背景动效
  -> 人物前景 matte 或经过验证的脸部安全遮罩
  -> 工具框、主标题、可读素材
  -> 字幕
```

- 降低不透明度不等于透明；准确 demo 有实心背景时要隔离 alpha 或建立遮罩。
- 人物、字幕和真实证据是主角；背景字不能穿脸，工具框不能挡脸。
- 观众画面只显示逐字稿或批准内容。诸如“提到工具名就给它证据”“步骤出现时让间距驱动它们”是导演备注，只能留在分镜文档。
- 真实 landing page/GitHub/Logo 进入后以可读性为先；不伪造品牌，不展示登录态或私人页面。

## 5. 开头实施顺序

1. `video-use` 用真实音频确认问题句、六步和下一句的边界，写导演时间线。
2. 确认是否采用风格库2与第五期基线；若采用，先加载本参考和五个已确认组件。
3. 对本期新增或替换的每张 Shotcraft 卡，读取 Gallery、完整镜头卡和准确 demo TSX。
4. 将本期逐字稿、品牌和证据素材填入现成节奏骨架；不把导演备注变成画面文案。
5. 先做全分辨率开头小样；检查人物遮罩、前后景、双框错峰、字幕、桥接插入和音频恢复点。
6. 用户确认具体小样后锁定版本；后续全片只能在该基线上扩展，不能无说明地换回旧版或另写一套近似开头。
7. 全片合成后再次抽查桥接代表帧，防止子组件在最终层级中被盖住。
