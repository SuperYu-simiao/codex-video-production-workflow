## 2. 视觉 DNA

### 2.1 总体气质

- 气质：理性、冷峻、带一点调查档案与实验室感，但会穿插幽默拟物。
- 叙事方式：不是用装饰特效填满画面，而是“每个抽象名词对应一个视觉隐喻”。
- 节奏：真人口播稳定讲述，概念段以 2-6 秒高密度包装打断；长截图段用舞台、电脑桌面和局部放大保持统一。
- 视觉重心：中央对象优先，左右对象辅助；每个段落只有一个主概念。
- 对比关系：暗舞台承载逻辑，明亮人物承载信任，蓝色 AI 素材承载能力，暖色实拍承载现实类比。

### 2.2 固定舞台

1. 黑灰背景，带极低对比度的数字、代码或档案纹理。
2. 下半屏是向地平线收束的透视网格，地平线大约在画面高度 `48%-56%`。
3. 底部可出现一张白/浅灰虚拟桌面和键鼠，建立“电脑工作台”空间。
4. 中央悬浮主对象：手机、文档、截图、人物头像、机构卡或搜索框。
5. 大标题可退到后景，形成巨型空间字，而不是普通平面标题条。
6. 灯光以中央亮、边缘暗为主，重要对象带柔和顶光、轮廓光或地面反射。

使用规则：黑、灰、白负责结构；每个镜头只使用一种强强调色。红色承担危险或失败，橙色承担章节和标签，蓝/紫/红分别标记三种 AI 档位。

### 2.4 字体

- 大标题：高对比宋体/明朝体，字面窄而有力量；白字、灰影或细描边，常放在后景。
- 警告标题：粗黑无衬线或压缩黑体，使用红/橙，字距紧。
- UI 与模式标签：中性无衬线，白底黑字或橙底白字。
- 技术元信息：小号等宽字体，作为背景纹理，不承担主要阅读。
- 字幕：底部白色粗体，黑色半透明底块或粗描边；当前重点词可用黄色。
- 不要把所有文字都做成故障字；故障只用于转折、失败和强问题。

## 3. 画面模块库

### S2-C01 黑色透视技术舞台

- 固定结构：暗纹背景 + 消失点网格 + 中央顶光 + 可选虚拟桌面。
- 用途：承接所有标题、文档、图标和隐喻镜头，是全片连续性的来源。
- 运动：背景几乎不动，只做 `1%-3%` 慢推或轻微视差；网格禁止高速滚动。
- 可替换：背景数字、技术线稿、桌面设备。
- 不可替换：中央消失点、暗场高对比和“对象站在舞台上”的空间感。

### S2-C02 3D 手机 + 关键词标题

- 结构：右侧斜立手机；左侧两级大标题；手机前后有轻景深。
- 动效：手机绕 Y 轴小幅旋转并前后推拉；标题从 Z 轴冲入，带方向性模糊，约 `0.25-0.5s` 落定。
- 适用：开头 hook、产品或机制揭示。
- 复用注意：标题只保留 4-8 个字，手机屏幕必须使用真实内容。

### S2-C03 中心文档 + 环绕评论卡矩阵

- 结构：中央长文档/账单，周围 6-8 张横向卡片，卡片朝中心略微透视。
- 动效：先看主文档，再从左右错峰弹出评论卡；或主文档缩回、评论卡向边缘扩散。
- 适用：证据很多、用户反馈、案例集合。
- 参数：卡片间隔 `0.08-0.16s`，位移 `4%-8%` 画宽，最终停留至少 `1.0s`。

### S2-C04 头像图标 + 概念能量场

- 结构：中央头像/产品图标，背景使用旋涡、光流或发光平台，上方一枚橙色胶囊标题。
- 动效：旋涡持续慢转；图标 `scale 0.85 -> 1`；标签下落；强化状态可增加手臂、盾牌等幽默图形。
- 适用：工具升级、模式切换、角色拟人。
- 边界：这是概念隐喻，不要伪装成真实产品 UI。

### S2-C05 三档齿轮/模式选择器

- 结构：快速、思考、专家三个并列齿轮或机械徽章；中心符号分别是闪电、大脑、盾牌。
- 动效：三档先同时稳定出现，被讲到的档位点亮并放大 `3%-6%`；颜色从蓝到紫再到红；可叠轻微色差和镜头呼吸。
- 适用：版本、套餐、能力等级、模式对比。
- 边界：不要三个齿轮一起强闪；一次只突出一个档位。

### S2-C06 轨道/半球式模式层级

- 结构：头像在中央竖轴，快/思考/专家标签沿半圆或球面排布，后景有巨大淡字。
- 动效：先出现一个档位，再向外展开轨道与其他档位；半球边缘做缓慢视差。
- 适用：从单一模式升级为多档系统。
- 参数：整体展开 `0.8-1.4s`，标签 stagger `0.12-0.2s`。

### S2-C07 巨型章节字 + 技术线稿

- 结构：2-6 个巨型宋体字位于后景；前景/两侧加入人物线稿、流程草图或案例图。
- 动效：字从暗灰到白，线稿用描边 reveal；中央案例图随后进入。
- 适用：章节切换，例如“顶层设计”“搜索”“质检”。
- 参数：标题落定后至少停 `0.6s` 再进入信息对象。

### S2-C08 失败拼贴 + 印章判定

- 结构：中心案例图，两侧撕边小卡；上方橙色结论；中央红色 `FAILED` 印章。
- 动效：两侧卡片先飞入，印章在落点 `scale 1.25 -> 1` 并轻震；顶部可出现 2-4 帧 RGB glitch。
- 适用：失败案例、错误方法、反例。
- 边界：印章只出现一次；停留需足够观众读懂失败原因。

### S2-C09 舞台上的真实网页/文档

- 结构：真实截图作为白色窗口悬在中央，底部有虚拟键盘与鼠标；必要时加第二窗口或局部放大框。
- 动效：窗口从远处推近，正文保持稳定；解释到局部时再叠加一个裁切放大窗。
- 适用：提示词、回答、规划、证据展示。
- 边界：不得把真实屏幕处理成看不清的小装饰；复杂文字至少停 `4-8s`。

### S2-C10 搜索栏 + 旧档案隐喻

- 结构：横向搜索框、放大镜、旧纸档案；后景巨字“搜索”。
- 动效：档案从下方升起，搜索框横向展开，关键词逐字出现，搜索后切到真实结果。
- 适用：检索、资料查证、先搜索再回答。
- 声音建议：键入声 + 一次确认 click。

### S2-C11 专家法庭/机构会审

- 结构：法庭/法槌类比专家判断；机构证件卡呈扇形后排，中央主卡依次切换；前方显示被审查文档。
- 动效：法槌镜头用快速推进；机构卡先展开，再把不同专家卡推到最前；文档作为审查对象保持稳定。
- 适用：专家审核、多模型交叉验证、质量把关。
- 边界：机构、人物和结论必须是真实或明确写成“概念示意”。

### S2-C12 多窗口推理 + 局部放大

- 结构：主文档右侧/居中，辅助回答窗位于左下；也可把真人缩成左侧竖屏 PIP，右侧保留证据页面。
- 动效：辅助窗从角落滑入；关键句做灰遮罩、放大或下划线；不同窗口不要同时滚动。
- 适用：边讲边看回答、对比思路与最终方案。

### S2-C13 AI 生成画面作为结果例证

- 结构：全屏插入 AI 人物或场景，使用清晰电影画面承接抽象说明。
- 动效：镜头间用短叠化，回到口播时用 `0.3-0.6s` 交叉淡化。
- 适用：展示生成内容的不确定性、风格漂移或效果差异。
- 边界：AI 画面是案例，不替代证据；必须与口播语义直接相连。

### S2-C14 逻辑盒/数据工地隐喻

- 结构：逻辑素材从纸箱中弹出；数据处理表现为工人在货架搬运蓝色“数据”箱。
- 动效：箱盖打开、对象上升；工地画面叠加白色模式卡，并通过卡片替换表示档位切换。
- 适用：上下文输入、素材整理、数据搬运、处理能力。
- 优点：把看不见的计算过程变成直观的物流动作。

### S2-C15 快速档故障字 + 质量档蓝图

- 快速档：白色大字叠加阴影复影、细微抖动和 RGB 分离，强调“快但粗”。
- 质量档：暗场人物/专家线稿、测量圆规与构图线，标题稳定、几乎无抖动，强调严谨。
- 两者必须形成运动反差：快档躁动，质检档克制。

### S2-C16 赛车引擎类比蒙太奇

- 结构：方向盘、发动机、换挡、赛车高速掠过、拉力车漂移，按“驾驶者—工具—档位—结果”展开。
- 剪辑：镜头长度约 `0.3-1.3s`，大量动作匹配与方向一致切；高速段使用运动模糊，结论镜头拉长到 `1.5-2.5s`。
- 适用：解释不同模式要按任务选择，而不是永远使用最强/最快模式。
- 边界：只在类比成立时使用，不要把赛车当无关炫技 B-roll。

### S2-C17 键盘俯拍 + 问题字卡

- 结构：键盘俯拍作为“操作者做决定”的落点；背景压暗，中央出现问题句。
- 动效：第一句平稳淡入，关键问题用一次 RGB glitch/横向错位，再恢复清晰。
- 适用：段尾设问、进入实操前的思考。

### 缓动与节奏

- 对象进入：`easeOutCubic` 或 `easeOutQuart`，不要默认弹簧弹跳。
- 大型窗口推近：`easeInOutCubic`，时长 `0.5-0.9s`。
- 隐喻镜头必须按“建立对象 -> 明确变化 -> 停留解释 -> 收束”四阶段完成。
- Glitch 只做 `2-6` 帧，不要在整段持续。
- 真实文档一旦进入阅读状态，停止无关背景运动。
- 每 `2-6s` 可更换一次信息形态，但不是每秒都必须切镜头。

## 7. 可复用导演模板

### 模板 A：概念解释段（5-8 秒）

| 阶段 | 时间 | 画面 |
|---|---:|---|
| 建立 | `0.0-0.8s` | 黑舞台与巨型章节字出现 |
| 对象 | `0.8-2.0s` | 主隐喻对象从 Z 轴进入 |
| 变化 | `2.0-4.5s` | 对象发生一次明确状态变化 |
| 证据 | `4.5-6.5s` | 真实截图/文档进入并稳定 |
| 收束 | `6.5-8.0s` | 对象退场或切回人物 |

### 模板 B：真人 + 证据分屏（6-12 秒）

- 左侧 `22%-30%` 为竖屏真人卡，暖色细边框。
- 右侧 `60%-70%` 为真实文档或网页。
- 背景保留暗网格舞台，但透明度降低。
- 右侧页面可滚动，左侧人物不做额外浮动。
- 关键字只在右页做一次灰遮罩/放大，不遮挡人脸。

### 模板 C：反例判定（4-6 秒）

- 中央真实案例先稳定 `1.0s`。
- 左右各进入 1-2 张辅助卡。
- 红色印章砸落，顶部橙色结论随后进入。
- 完整失败画面停 `1.0-1.5s`。
- 用 zoom blur + 白闪转到改进操作。

### 模板 D：多档模式（5-7 秒）

- 三个并列对象同时出现，但默认都低亮。
- 按口播顺序逐个点亮，上一档在下一档亮起时降回基础亮度。
- 蓝/紫/红只表示不同档位，不在同一对象上混色。
- 最终三档同时保持 `0.8s`，再切真人或证据。

### 模板 E：现实类比蒙太奇（6-12 秒）

- 先给操作者动作，再给工具内部，再给档位动作，最后给结果全景。
- 前半段单镜 `0.3-0.8s`，后半段结论镜头 `1.5-2.5s`。
- 所有镜头必须围绕同一个类比，不混入“只是很酷”的无关画面。

## 8. 声音建议（非源片观察）

源 MOV 没有音轨，以下仅为实现建议，不能视为参考片事实：

- Z 轴标题：短促低频 whoosh。
- 卡片展开：低存在感 tick，最多 2-3 个代表声，不为每张卡配音。
- 模式点亮：soft click + 轻电子音高变化。
- 失败印章：单次低频 impact。
- Glitch：`80-180ms` 数字噪声，不能盖住人声。
- 搜索输入：3-5 个轻键入声 + 一次确认 click。
- 法槌/机构切换：一次木质 hit + 轻卡片 swish。
- 赛车蒙太奇：以原始机械声为主，转场 whoosh 要克制。

## 9. 不可误学的部分

1. 不要把抖音右侧交互栏、头像、点赞/评论/分享数字收进模板。
2. 不要把左下角账号、标题、进度信息当成科技 HUD；它们是平台叠层。
3. 不要全片一直 glitch。参考里 glitch 只承担失败、强问题和章节跳转。
4. 不要让黑色网格变成高亮赛博朋克；网格应低对比、安静、服务空间定位。
5. 不要用虚构网页、机构、专家或数据冒充真实证据。
6. 不要把所有概念都做成齿轮；真正值得复用的是“抽象词 -> 具体隐喻”的方法。
7. 不要让巨型标题、底部字幕和中央证据三者同时争夺注意力。
8. 不要在文档阅读时让背景旋转、粒子飞舞或页面不停缩放。
9. 不要把 B-roll 仅当氛围图；每一段 B-roll 都必须与正在说的概念形成因果或类比。

## 10. 制作验收清单

- [ ] 口播、人脸、手势和底部字幕是否没有被遮挡？
- [ ] 平台 UI 是否已经排除？
- [ ] B-roll 是否真正解释了当前句子？
