# AI 剪辑参考会话沉淀：第7期《workbuddy 自动整理知识库》

版本：2026-09-14 · 按第7期实际剪辑过程整理。用途：把 AI 剪辑的**过程、沟通反馈、Skills、插件与工具**沉淀成可复用工作流，并把第7期实际做出来的**画面呈现、切换动效、节奏、动效丰富度**作为后续要达到的质量基准。逐字稿的具体内容（这期视频讲什么）与工作流无关，本文不记录视频主题内容，只记录"怎么用 AI 把这期剪出来、剪成了什么样"。

## 1. 这份文档记什么

- **AI 剪辑的完整过程**：从素材和逐字稿进来，到成片出去，每一步做什么、由哪个 skill 负责。
- **沟通/反馈过程**：用户在中途提出了哪些修改要求，这些要求形成了什么规则。
- **Skills / 插件 / 工具**：本机实际用了哪些，各自负责哪一段。
- **特效 → 语义 → 插入方式 → 画面怎么动**：一套可复用的映射。
- **第7期质量基准**：画面呈现、切换动效、节奏、动效丰富度——这是"想要的效果"的具体样子。
- 逐字稿内容只是"这期视频的素材"，换成任何一期都一样；它不进工作流。

## 2. 用到的 Skills / 插件 / 工具

| 工具 | 类型 | 在剪辑里负责什么 |
|---|---|---|
| `video-use` | Skill | 导演与时间线：逐字稿、真实口播时间、句级边界、字幕、人物状态、插入段和源帧到母版的统一映射 |
| `video-shotcraft` | Skill | 特效配方库：校验卡名和 `style-key`、读完整镜头卡和准确 demo TSX、提供运动机制 |
| Remotion | Codex 插件 + 库 | 按导演时间线分轨合成、预览、渲染 |
| 风格库2 | 视觉参考 | 视觉底盘：黑灰透视网格、概念隐喻、真实网页/文档证据、克制故障感 |
| FFmpeg / ffprobe | 系统工具 | 底层音视频处理、抽帧、响度/黑帧/解码 QA |
| ChatCut | 可选插件 | 需要交付可编辑工程（剪映）时使用 |

一句话分工：**video-use 指挥 → video-shotcraft 提供准确特效 → Remotion 按轨道合成 → 风格库2 定视觉底盘**。特效名相同不等于观感相同；只拿特效名手写"看起来像"的动画，结果会像"特效功能演示"而不是成片。

## 3. AI 剪辑的完整过程（第7期实际走了一遍）

1. **进素材 + 逐字稿**：用户提供粗剪真人口播视频、录屏素材和逐字稿，要求"按真人口播 + 之前剪视频的 skill + 风格库2"设计包装方案。
2. **设计包装方案**：产出包装方案、补录素材清单、官网/GitHub 截图素材表、结构化特效映射、导演分镜。此阶段只规划，不剪辑、不采集、不渲染。
3. **用户逐条指定特效 → 语义映射**（见第4节）。
4. **用户指定特效密度**："特效最好 2–3 句就加入一个"→ 把逐字稿拆成语义句群节点，每个节点只一个主动效，接缝用明确 style-key。
5. **先做开头小样**：不直接剪全片，先出开头方向小样供审核。
6. **看小样逐点反馈**：用户针对具体画面提修改（人物裁切、正方形小窗、人脸居中、画面切换要有移动/渐显等），改完再出下一版。
7. **追加/补充特效卡**：用户继续指定新的特效卡和触发句，补进映射。
8. **确认后剪全片**：按确认过的方向扩展到全片，做独立终检。
9. **字幕校正**：成片后如字幕与口播对不上，只改字幕层，不动音轨、画面、动效和人物裁切。

关键顺序：**先方案 → 再小样 → 逐点反馈 → 确认后再扩展全片**。不要跳过小样直接剪全片，也不要在方案未确认时先堆特效。

## 4. 特效 → 语义 → 插入方式 → 画面怎么动（可复用规则）

语义是"类型"不是"具体句子"：换一期视频，同样的语义类型套用同样的特效，只把触发句换成本期真实口播。

### 4.1 结构类（章节、工具、步骤、转场）

| 语义类型 | 特效卡（style-key） | 怎么插入 | 画面怎么动 |
|---|---|---|---|
| 小标题 / 进入新章节 | `aurora-bloom-bg-flip` | 章节接缝处，约 0.8–1.0s 酝酿、翻色约 0.36s | 旧标题 blur-out → 留空档 → 新标题 blur-in 后落定稳定 |
| 提到工具 / Skill 名（首次） | `assemble-then-type-flyin` | 背景大字先退场；左框按"骨架 → 标题 → 文字"组装；右框放该工具 **landing page / GitHub 首页 / Logo 截图**，比左框延迟约 0.3s | 左框工具名逐字 3D 落位；右框轻位移、轻缩放、短景深模糊落定；两框错峰不硬弹；落定后停止运镜 |
| 提到工具 / Skill 名（重复） | 同一工具卡短召回 | 复用已组装卡片，只 0.4–0.8s 短飞入/高亮 | 不重新搭骨架、不重播完整动效 |
| 步骤（下载/理解/整理、"一共六步"式） | `autolayout-gap-dial` | 步骤块数量换成本期真实步数 | 数字、测量线、坐标、块位置由同一个 gap 参数同帧驱动，最后收成进度轨 |
| 问题句/停顿句后的转场 | `card-flock-tumble` + BGM | 真正暂停源视频、插入独立桥接，桥接结束后从同一源帧恢复 | 步骤卡翻滚聚拢、约 10 帧内坍缩、烟环吞画面；BGM 从人声结束后起、恢复口播前收尾，不压人声 |
| 不同工具之间的转场 | `bubble-swarm-takeover` | 工具段接缝处插入 | 气泡群吞掉上一个工具画面，露出下一个工具 |

### 4.2 开头类（前几秒丰富画面）

| 语义类型 | 特效卡（style-key） | 怎么插入 | 画面怎么动 |
|---|---|---|---|
| 开场快速吸引 | `graze-face-tour` | 开头 1 秒左右 | 快速巡礼飞入，光条/面板掠过 |
| 透明强调词 | `gradient-word-sweep` | 用透明图层，透出人物 | 关键词渐变扫过，人物可见 |
| 背景跑马文字 | `neon-triple-marquee` | 放在人物与背景之间（透明） | 多行跑马文字在人物背后运动，仅当前行高亮 |
| 基础工具总述句 | `avatar-grid-radial-build-colorize` | 开头"基础工具"那句 | 头像/图标网格径向展开并上色 |
| 特定强调句 | `element-body-moves · axial-stretch`、`glow-flyline-moves · glow-orb-ambient`、`impact-feedback · hit-counter` | 按用户指定的那句触发；卡片内容换成本期工具 logo / 官网首页截图 | 元素轴向拉伸、光流环绕、撞击计数反馈 |

### 4.3 工具介绍类（介绍某个工具时）

| 语义类型 | 特效卡（style-key） | 怎么插入 | 画面怎么动 |
|---|---|---|---|
| 工具逐行详细介绍 | `ai-stream-response` | 工具名飞入后 | 介绍文字一行一行流式写出 |
| 工具介绍期间的辅助演示 | `canvas-materialize-moves · panel-to-canvas`、`chart-live-moves · oscilloscope-stream`、`carousel-3d`、`counter-confetti`、`command-palette-summon` | 每个工具介绍期间至少 2–3 个，按内容选 | 画板物化、示波器/图表实时、3D 轮播、计数彩带、命令面板弹出 |

### 4.4 人物小窗（必须项）

- 展示录屏、工具证据、文档、步骤时，人物统一裁成 **1:1 正方形小窗**（约 220×220），放右下角或左上角；信息密集时隐藏人物。
- 小尺寸裁切必须**按人脸焦点居中**，不是机械对称裁切——用户原话："这一点是必须的"。

## 5. 第7期质量基准：实际做成什么样

这是第7期最终导演时间线的落地结果，作为"想要的效果"的具体样子。30fps、1920×1080；源片 8035 帧（约 267.8s），母版 8165 帧（约 272.2s）。

### 5.1 画面呈现（人物状态系统）

| 状态 | 含义 | 用法 |
|---|---|---|
| `P0` 全屏真人 | 源片 16:9 全屏，保留胸口手势 | 口播直接叙述、开头结尾、收尾承诺 |
| `P1-R` 右侧竖屏 | 4:5 圆角竖窗，宽约 27%，保留肩部手势 | 信息面板与人物并存的过渡态 |
| `P2` 正方形小窗 | 1:1，约 220×220，右上 `P2-TR` 或右下 `P2-BR` | 展示录屏、工具证据、文档、步骤时 |
| `P3` 隐藏人物 | 人物隐藏，但源音频连续不中断 | 全屏读文档、代码、工具详细页、章节门 |

- **人脸焦点居中**：实际按面部焦点追踪裁切（焦点 x 约 66.1%–66.7%），把"脸"落到正方形中心，而不是几何对称裁切。实现规则：保留源片全高，水平按 `50 - focalX × 16/9` 百分比平移。
- 人物小窗位置随 UI 避让：关键 UI 在右下就放左上，反之亦然；冲突时隐藏人物。
- 视觉底盘始终是风格库2：黑灰透视网格、概念隐喻、真实证据页，不是纯黑背景。

### 5.2 切换动效（转场系统）

| 转场 | 用在哪 |
|---|---|
| `aurora-bloom-bg-flip` | 章节门：进入新大段时统一翻页（全片约 4 处章节门） |
| `card-flock-tumble` | 停顿桥接：问题句后真正暂停 + 独立 BGM |
| `bubble-swarm-takeover` | 工具与工具之间的切换 |
| `mask-wipe` / `line-carry-transition` | 普通接缝的移动/渐显过渡 |
| `shared-element-morph` / `card-flip-reveal` / `blinds-slice` | 概念对比、双路径、卡片翻转 |
| `paper-plane-messenger` | 手机端 → 电脑端的交接 |
| `bridge border release` | 暂停桥接结束、恢复口播时的边框释放 |

规则：**每次切换画面要有移动或渐显，不做生硬跳切**；同一视觉状态内的口误精剪才允许干净跳切。

### 5.3 节奏（密度与停留）

- 全片 32 个视觉段，每段**一个主动效**，段与段之间用转场连接。
- **工具段**（yt-dlp / Whisper / whisper.cpp / SiliconFlow / FFmpeg）每个都用固定组合：`bubble-swarm-takeover` 转场 → `assemble-then-type-flyin` 工具名飞入 → `ai-stream-response` 逐行介绍 → 再加 1 个辅助演示特效。即**每个工具介绍期间至少 2–3 个特效**。
- 概念段（模型边界、双路径、卡片翻转、关键帧密度等）每段一个"概念隐喻"动效，不堆叠。
- 每个高能动作落定后保留 **1.0–2.5s 稳定阅读时间**；真实网页/文档进入阅读态后停止运镜。
- 特效密度由语义驱动（约 2–3 句一个节点），不是每句都堆。

### 5.4 动效丰富度（实际用到的完整特效清单）

按用途分组：

- **开场**：卡通演示（左）、`element-body-moves · axial-stretch`、`glow-flyline-moves · glow-orb-ambient`、`impact-feedback · hit-counter`、克制的标题揭示（风格库2纵深文字）。
- **停顿桥接**：`card-flock-tumble`（源片第 954 帧冻结，插入 130 帧，恢复时仍从第 954 帧继续）。
- **步骤**：`autolayout-gap-dial`。
- **概念隐喻**：`radial grid build`、`bezier convergence`、`card-flip-reveal`、`panel fade/move`、`shared-element`、`staggered cards`、`frame selection`、`paper-plane-messenger`。
- **工具介绍**（5 个工具共用）：`avatar-grid-radial-build-colorize`、`assemble-then-type-flyin`、`ai-stream-response`，再各自配 `counter-confetti`、`carousel-3d`、`oscilloscope-stream`、`panel-to-canvas`、`command-palette-summon`、`autolayout-gap-dial` 中的一个。
- **章节门 / 转场**：`aurora-bloom-bg-flip`、`bubble-swarm-takeover`、`mask-wipe`、`line-carry-transition`、`shared-element-morph`。

## 6. 沟通/反馈形成的规则（中途改了哪儿）

1. **特效密度**："特效最好 2–3 句就加入一个"→ 句群节点化，每节点一个主动效，不每句堆。
2. **人物裁切**：正方形 1:1 小窗，人脸焦点居中，右下/左上交替；信息密集隐藏。
3. **画面切换**：每次切换画面要有移动或渐显，不做生硬跳切。
4. **工具名飞入**：统一 `assemble-then-type-flyin`，右框放真实官网/GitHub/Logo 证据。
5. **工具逐行介绍**：`ai-stream-response` 一行行写出。
6. **转场**：工具间 `bubble-swarm-takeover`；章节门 `aurora-bloom-bg-flip`；停顿句 `card-flock-tumble` + BGM。
7. **字幕校正**：只改字幕层，不动口播音轨、画面、动效和人物裁切。

## 7. 关键教训（可直接进工作流）

1. **特效名相同 ≠ 观感相同**：必须读完整镜头卡和准确 demo TSX，继承其缓动、时值、纵深、运动模糊和布局，再替换本期内容。
2. **导演时间线来自真实口播**：时间码不能按逐字稿字数比例估算；要词级/句级对齐真实音频后再触发动效。
3. **暂停必须真正拆源轨**：插入转场时停住源视频和源音，转场结束从同一源帧恢复，后续轨道统一补偿；"静音 + 盖一张定格图"会让恢复点跳过一段口播。
4. **导演备注不进观众画面**："提到工具名就给它证据""步骤出现时让间距驱动它们"这类是制作说明，只能留在分镜文件；观众画面只显示逐字稿或批准素材。
5. **高清源评审**：供用户判断视觉效果的小样直接读原始高清素材；低清代理只用于内部排错。
6. **隐私脱敏**：录屏和截图去掉真实用户名、任务名、本机路径、密钥、余额等；工具身份用公开官网/GitHub/Logo 证明；手机端消息用明确标注的合成演示界面。
7. **「无留白」≠「人脸居中」**：PIP/侧栏裁切修复时，只验证框内无黑边（letterbox）不够，必须先定位源片人物面部焦点（ffmpeg rawvideo 逐像素肤色簇峰值/分位），再据此设 `objectPosition`；源片人物偏右时中心裁（50%）会把脸挤到框右缘并切掉右臂。
8. **浮层文字不套底框**：口播画面上的轻量文字标注（工具名、关键词、Codex 标识等）用纯文字 + textShadow，与字幕同风格；深色圆角底框只留给真正的卡片/按钮类 UI，不用于文字标注。
9. **装饰骨架不与正文重叠**：无字骨架/装饰元素落位后必须核查与正文文字的重叠（尤其工具名列表区）；改一处后要全片扫同类问题，不要只修当前句。

## 8. 复用指南

1. 新一期开始时，先按第3节过程走：进素材 → 方案 → 用户指定特效映射 → 小样 → 反馈 → 全片。
2. 特效映射按第4节的"语义类型"套用，触发句换成新一期真实口播，不复制某一期的具体句子或帧号。
3. 画面呈现、转场、节奏、动效丰富度对齐第5节的质量基准：人物状态系统、每段一个主动效、工具段固定组合、稳定阅读停留。
4. 确定使用某张卡时，读 Gallery 索引、完整镜头卡和准确 demo，不凭效果名重写。
5. 用户批准的每个小样成为后续基线；修改其他片段时不重置已满意组件。
6. 每期把新增特效卡和新的反馈规则补记回本文，让沉淀随使用增量更新。
7. 特效自动选型模板见 [`特效使用模板.md`](特效使用模板.md)：根据逐字稿语义/素材切入点/场景切换直接选特效，不再逐句询问用户。
