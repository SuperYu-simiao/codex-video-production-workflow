# 需要补录的操作素材

下列时间码均为原片的规划级约数。问题句后插入 4.5 秒 `card-flock-tumble` 后，同一句在包装母版中的时间约为原片时间 + 4.5 秒。你不需要把录屏剪好，每组录一条连续操作即可，后期会按逐字稿原句拆分。

## 逐字稿对应索引

| 录屏组 | 从哪句话开始需要操作素材 | 到哪句话结束 | 优先级 |
|---|---|---|---|
| R1 | “第一步，先把剪辑工具接入 Codex。” | “分别负责后面的视觉包装、时间线和底层处理。” | 必须 |
| R2 | “我先用自己的照片生成 16:9 人物母图……” | “句尾自然下落。” | 重要 |
| R3 | “文案确认以后，我会始终使用同一个克隆音色……” | “这条完整旁白才是整条视频唯一的声音基准。” | 必须 |
| R4 | “现在把人物母图和这条旁白交给 HeyGen……” | “数字人口播母片。” | 必须 |
| R5 | “第三步，把母片交给 video-use 做基础粗剪。” | “声音连续、内容完整的基础版本。” | 必须 |
| R6 | “第四步，确定这条视频的视觉语言……” | “再沉淀成我自己的视觉规则。” | 重要 |
| R7 | “第五步，让 video-use 生成包装方案。” | “以后才进入制作。” | 必须 |
| R8 | “第六步，补齐画面信息，再生成成片。” | “检查 HeyGen、爆音、错字、糊脸、嘴型和穿帮。” | 必须 |

这里的句子沿用用户提供的逐字稿；`Remotion / FFmpeg / 眼神 / 黑帧片段 / 爆音` 等疑似转写词，录屏时按真实工具或真实检查项操作，最终字幕等对照原音后再定。

## R1 工具链安装与配置（必须，无法复现安装时可录“已安装验证”）

对应口播约 00:20-00:42：

> “第一步，先把剪辑工具接入 Codex。”
>
> “我先安装 video-use，再完成 ElevenLabs API 的配置。”
>
> “HyperFrames、Remotion 和 FFmpeg 也会提前接入……”

需要录：

- 在 Codex/终端中找到并安装或验证 `video-use`，停在明确的成功状态。
- 展示 ElevenLabs 配置入口和“已配置/可用”状态。绝对不要录入、显示或回放 API Key；敏感字段保持遮罩。
- 展示 HyperFrames、Remotion、FFmpeg 已接入或版本检查的结果。不要为了录屏重复卸载、重装或破坏当前环境。
- 建议原始长度 25-40 秒；每个成功状态停 2 秒。

## R2 人物母图、声音样本与克隆音色（重要，可由真实前后截图补一部分）

对应口播约 00:54-01:15：

> “我先用自己的照片生成 16:9 人物母图……”
>
> “再从以前说话的视频和长录音中挑出没有背景音乐、口音最自然、人声最干净的部分，用来克隆我的音色。”
>
> “我还会把自己喜欢的语速、停顿和重音整理成一套表达规则……”

需要录：

- 从本人照片生成 16:9 人物母图的关键操作：选择图片、输入要求、生成、查看最终母图。
- 选择干净视频/长录音样本时只展示必要片段和波形，隐藏私人文件名、聊天记录和无关人物。
- 在 ElevenLabs 中创建/选择克隆音色并试听成功状态；隐藏账号邮箱、Voice ID 和所有密钥。
- 表达规则如果已经是文档，录打开文档并依次定位 `语速 / 停顿 / 重音`；没有现成文档则提供文字即可，不需要为了画面新造假界面。
- 建议原始长度 35-60 秒。

## R3 连续旁白与 FFmpeg 处理（必须）

对应口播约 01:15-01:33：

> “先生成一条覆盖全文的连续原音频……”
>
> “然后用 FFmpeg 压缩过长的停顿，统一语速和响度，再处理片段衔接处可能出现的爆破声……”

需要录：

- ElevenLabs 中选择固定克隆音色、放入全文、生成连续旁白并出现可下载结果。
- 终端中运行真实 FFmpeg 处理命令，并停在成功输出；如果命令或路径含私人信息，先用可公开副本替换。
- 最好补一个处理前/后的波形或音频统计对比，能看出长停顿被收紧、响度被统一。
- 建议原始长度 30-45 秒。命令行画面至少稳定 2 秒，不能快速扫过。

## R4 HeyGen 数字人口播生成（必须）

对应口播约 01:33-01:43：

> “现在把人物母图和这条旁白交给 HeyGen……得到一条可以正式进入剪辑流程的数字人口播母片。”

需要录：

- 新建 HeyGen 视频/Avatar 项目。
- 上传或选择人物母图，上传完整旁白，确认 16:9 和对应头像/音频。
- 点击生成后展示任务状态；不用录完整等待过程，可以另录生成完成后的预览和导出入口。
- 隐藏账户余额、邮箱、历史私人项目和任何可识别客户内容。
- 建议原始长度 25-40 秒。

## R5 video-use 基础粗剪（必须）

对应口播约 01:43-02:06：

> “第三步，把母片交给 video-use 做基础粗剪。”
>
> “数字人需要检查眨眼、眼神、嘴型、手势、黑帧片段、接缝和音画同步。”
>
> “video-use 不会直接开剪，它会先给出一份处理方案，我确认以后它才开始执行……”

需要录：

- 把母片交给 video-use/Codex，并发出“先分析、先给处理方案”的真实指令。
- 展示方案里对眨眼、眼神、嘴型、手势、黑帧、接缝、同步等项目的检查结果。
- 展示你的确认/修改回复，再展示执行状态和基础版本产物。
- 对话或终端里如有本机用户名、私人绝对路径、Token 或其他项目名，录制前先做脱敏。
- 建议原始长度 35-60 秒。

## R6 视觉语言输入与规则沉淀（重要，可由截图和规则文档代替部分录屏）

对应口播约 02:06-02:20：

> “我会给 Codex 一些自己喜欢的视觉方向……”
>
> “它会把这些审美偏好整理成适合这条内容的色彩、构图、节奏和信息层级……”

需要录：

- 把视觉参考/截图交给 Codex，或打开已经使用过的参考文件。
- 展示 Codex 生成的视觉规则，至少能看见色彩、构图、节奏、信息层级四项。
- 如果参考图没有公开授权，录屏只展示局部或换成允许公开的参考副本。
- 建议原始长度 20-30 秒。

## R7 包装方案生成与确认（必须）

对应口播约 02:20-02:44：

> “第五步，让 video-use 生成包装方案。”
>
> “每一段要强调什么，画面怎样变化……哪些部分需要动态呈现，哪些部分应该保持克制……”
>
> “我确认可以继续修改以后，才进入制作。”

需要录：

- 发出生成包装方案的真实指令。
- 展示方案结果，慢慢定位到 `重点 / 画面状态 / 人物位置 / 素材 / 动效 / 克制段落` 等信息。
- 展示你的修改意见或批准回复，确保观众能看见“先方案、后制作”的门槛。
- 不要快速滚完整长文；分 3-4 个语义停点，每个停 1.5-2 秒。
- 建议原始长度 30-50 秒。

## R8 补素材、工具调度、小样与 QA（必须）

对应口播约 02:44-03:11：

> “根据确认后的方案，我会把每一段需要表达的信息准备完整……”
>
> “video-use 再调度 HyperFrames、Remotion 和 FFmpeg，把方案真正做出来。”
>
> “先生成一小段测试……再分段完成整条视频……逐段抽帧和视听检查……”

需要录：

- 当前视频项目的素材目录或素材清单从缺失到齐全的状态；只展示本项目，不带出其他私人项目。
- video-use 调度 HyperFrames、Remotion、FFmpeg 的真实任务/执行状态。
- 小样预览：颜色、排版、节奏、人物清晰度能同时看见。
- 分段制作结果或时间线总览。
- 最终 QA：逐段抽帧/接触表、播放检查和包含 `HeyGen / 爆音 / 错字 / 糊脸 / 嘴型 / 穿帮` 的核对清单。
- 建议原始长度 45-75 秒，可拆成“工具调度”和“QA”两条录屏。

## 统一录制规格

- 1920x1080，优先 25fps，与原片一致；系统缩放保持稳定。
- 鼠标指针可见，关键点击前停 0.5 秒，点击后停 1.5-2 秒。
- 每条操作前后各留 2 秒静止把手，关闭通知、聊天浮窗和自动填充提示。
- 不录 API Key、Token、邮箱、Voice ID、私人文件路径、客户名、余额或未公开项目。
- 录屏原声默认不会进成片，旁白仍使用当前视频的连续音轨。
